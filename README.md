# HM AppKit

Windows 装机助手：选择岗位、软件和安装位置，一键依次安装。安装时自动复用本地缓存并检查官方更新，第三方安装包单独存放，不嵌入助手，也不随发布压缩包分发。

v0.16 提供 GitHub 到 Gitee 的代码与发行版附件自动同步工作流，配置仓库凭据后随发布执行。助手更新继续优先检查和下载 Gitee 正式版，网络失败时回退 GitHub；两边都必须提供同标签的正式包与 SHA-256 校验文件。配置和业务安装包缓存继续保留。

## 使用

1. 打开 `HM AppKit.exe`。适用于 Windows 10/11 x64，发布包自带 .NET 运行时。内置应用使用官方直连；自定义 WinGet 应用需要微软应用安装程序（WinGet）。
2. 无需选择安装来源。安装时先检查 `HM AppKit.exe` 旁的 `Local Installer`：没有包则从官方渠道下载并保留；已有包则检查更新，无更新直接复用，新包通过校验后才替换旧缓存。
3. 点击“安装位置”中的目标盘，蓝色边框与底色表示当前选择。只显示可识别为内置固定磁盘的卷，排除 USB/UASP 外接硬盘、固态 U 盘、普通 U 盘等可移动设备。默认优先 D、E、F 等数据盘，最后选 C；点击“默认”可恢复自动选择，已选磁盘不可用时会阻止安装。
4. 默认安装到 `所选盘:\Software\应用目录名`。点击根目录旁的铅笔图标修改，每款软件也可通过卡片右侧铅笔图标单独指定目录。
5. 按岗位点击圆点多选应用，或输入名称搜索软件，点击“一键安装”。选中时显示实芯与淡色光晕，仍支持独立多选。已选数量、全选和清空位于搜索框左侧，按钮位置固定。运营和客服共享的软件只安装一次，详细日志收在可展开区域。
6. 安装包始终保留在程序目录的 `Local Installer` 文件夹，无需指定缓存目录。它与 `D:\Software` 等应用实际安装目录分开；每款应用有独立的缓存索引和文件夹。

安装包检查由安装队列触发，打开助手不会批量下载或刷新业务软件安装包。仅启动助手不会安装软件；点击安装会接受所选软件及适用的 WinGet 源协议，可能出现管理员权限确认。安装时逐项检查配置和目标目录，默认先检查是否已安装，已安装的应用会直接跳过。无需先生成安装预览。

底部圆角进度条显示整个安装队列的处理进度，同时显示百分比和已结束的应用数量。成功、原已安装、失败、被阻止、取消和待核验均属于已有最终结果的项目，因此 100% 表示队列处理结束，具体安装结果仍以卡片状态及结果摘要为准。检查、下载和当前应用安装期间显示实时操作文案，百分比按各应用的最终结果推进，不代表厂商安装器内部百分比。“静默安装”开关关闭后，应用名后的模式标签同步改为灰色“常规”；京麦等常规安装项保持灰色。开关选择随配置保存。

卡片右侧的状态点表示安装进度：灰色“待安装”、黄色“安装中”、绿色“已安装”。已安装应用的位置也会核对；目录不符或缺少有效位置证据时显示警告并跳过，不自动迁移或重装。结束汇总分别显示本轮新安装、已安装跳过及需关注，悬停可看详细原因。状态由安装队列反馈，打开助手不会为改变圆点而自动安装软件。

## 放在 U 盘使用

将完整程序文件夹复制到可写 U 盘，例如 `U:\HM AppKit\`，从中打开 `HM AppKit.exe`。已有的 `Local Installer` 可一起复制，缓存记录使用相对路径，U 盘盘符改变不需要重新指定来源。程序目录和安装目标互相独立，U 盘内的助手可以把应用安装到电脑的 `D:\Software`、`E:\Software` 或其他已选择的内置盘。

U 盘需要有足够空间保存安装包，安装期间保持连接。配置和日志属于当前电脑，保存在该电脑的 AppData；程序与缓存可携带到其他电脑，旧电脑的绝对安装目录设置不会随 U 盘转移。为使用 HM AppKit 自身更新，请保留独立的程序文件夹，不要把程序文件直接散放在盘符根目录。便携运行的路径验证与硬件实测范围见 [v0.7 说明](docs/hm-appkit-v0.7.md)。

## HM AppKit 自身更新

从 v0.6 开始，打开助手会检查正式版更新。v0.15 起优先查询 [Gitee 发行版](https://gitee.com/huanmeng-it/HM-AppKit/releases)，Gitee 暂不可用或没有新版时查询 [GitHub Releases](https://github.com/19016563235/HM-AppKit/releases/latest)。Gitee 下载遇到临时网络错误时，可回退至 GitHub 同一标签，重新取得其元数据和校验文件；哈希、程序版本及来源校验不通过时停止更新。有更新时显示版本提示，下载并校验后确认重启替换程序文件。安装业务软件期间不会替换助手，网络失败不会影响当前版本继续使用。

更新在原程序目录进行，不需要搬移文件夹。`%LocalAppData%\HM AppKit\settings.json` 中的岗位、安装路径和选项，以及程序旁的 `Local Installer` 缓存均保留；自定义过的 `Data/catalog.json` 也会保留。下载的更新包与业务软件安装包分开存放。

**v0.5 没有助手自身更新功能，需要手动升级一次到 v0.6。** 从 Releases 下载压缩包，关闭旧助手，解压到原程序目录并覆盖程序文件，保留原来的 `Local Installer` 文件夹；配置位于 AppData，不需要复制。之后可直接使用启动时的新版提示。详情见 [更新说明](docs/self-update.md)。

七款平台软件记录了历史本地参考包的文件名、SHA-256、厂商签名和安装参数。手动放入 `Local Installer` 根目录且与参考记录一致的安装包可校验后导入受管缓存，再检查官方更新，原始手动文件不删除；不匹配的文件不会直接执行。公共软件和剪映使用各自的官方渠道及受管缓存，不需要切换模式。外接盘可提供安装文件和运行助手，但不能作为业务软件安装目标。

历史缓存复用、京麦实际安装及卸载清理结果见 [v0.5 验证记录](docs/hm-appkit-v0.5-test-2026-10-15.md)，自动缓存及便携使用见 [v0.7 验证说明](docs/hm-appkit-v0.7.md)，安装修复见 [v0.14 说明](docs/hm-appkit-v0.14.md)，本版更新源接入见 [v0.15 说明](docs/hm-appkit-v0.15.md)。公开的 [测试摘要](evidence/README.md)保留版本、签名、哈希和核验结果，已脱敏测试人员的用户目录与随机临时目录；完整主机快照和厂商安装包不公开。

## 安装行为

- 默认优先静默安装；京麦等明确配置常规安装的应用会显示向导并预填目标目录。UAC、依赖安装、占用文件提示和厂商首次启动界面仍可能出现。
- 程序目录与聊天记录、素材、草稿、缓存目录不同，后者按应用自身设置管理。
- 修改目录不会搬迁已安装的软件，默认跳过现有软件。
- 官网直连仅接受配置中允许的 HTTPS 域名，下载后验证 Windows 数字签名与厂商名称；从 WinGet 清单解析的下载还核对清单中的校验值。
- 缓存包使用前重新校验 SHA-256 和厂商签名；缓存固定存放于程序旁 `Local Installer`。发现官方新包时先下载并核验，再提交新索引并清理旧受管文件，下载或校验失败保留原包。
- 无网络且已有校验通过的缓存时可复用，日志明确说明无法确认官方最新版。没有可用缓存时下载失败会停止该项，不会执行未知安装包。
- 版本请求和下载流的临时网络错误最多尝试 3 次，间隔 1 秒、2 秒。下载中断后从头重新获取，半包不进入正式缓存。签名、哈希、来源白名单、元数据格式和本地磁盘错误不自动重试，厂商安装本身也不自动重试。取消和原有时间限制仍有效。
- 网络失败日志显示查询／下载阶段、实际请求域名、尝试次数和异常链错误码；不会记录完整签名下载地址及其查询参数。同一失败的详细记录不再与状态消息重复。
- 安装后核对目标位置，无法确认时显示“待核验”，不会仅凭退出码声称目录正确。
- 停止会等待当前安装结束再停止后续队列，不回滚已经完成的安装。

配置保存在 `%LocalAppData%\HM AppKit\settings.json`，日志位于同目录的 `Logs\`。升级依次检查 HM AppKit、HM-AutoSetup、FoxDeploy 的配置，保留自定义应用、各应用目录和安装选项，旧文件保留。v0.7 统一将旧来源模式、缓存目录和保留开关转为自动缓存；更早版本的默认根目录 `CompanyApps` 会更新为 `Software`，用户自定义安装目录保持原值。

## 维护软件目录

默认目录嵌入 EXE，不含厂商安装程序。统一维护时，将源码 `catalog/catalog.json` 复制到 EXE 旁的 `Data/catalog.json`，该文件会覆盖内嵌目录。

`PackageId` 用于自定义 WinGet 项；`OnlineInstaller` 配置官网动态地址、允许域名和签名发布者；`LocalInstaller` 配置可手动导入的外置文件名、SHA-256 与安装参数。`Roles` 可让同一软件属于多个岗位，应用 `Id` 保持唯一。只有本地配置的自定义应用只能核验并使用该包，需补充官方来源后才能自动检查新版。替换本地参考版本前需重新核验，不能只改文件名或忽略哈希。

全部内置应用均配置了官方安装来源，使用自动缓存策略。仅有 `PackageId` 的自定义项仍由 WinGet 管理下载及安装，无法在助手的 `Local Installer` 中保留原包；需添加 `OnlineInstaller` 后才能使用该缓存策略，卡片提示会明确说明。

## 构建

安装 .NET 10 SDK，在包含 `FoxDeploy.sln` 的源码根目录执行：

```powershell
.\scripts\Build.ps1
```

版本统一维护在 `Directory.Build.props`。v0.16 发布位置为 `artifacts/HM-AppKit/v0.16/win-x64/HM AppKit.exe`，压缩包为 `artifacts/HM-AppKit/v0.16/HM-AppKit-win-x64.zip`，同目录生成 `.zip.sha256`。后续版本的输出目录由版本号自动推导。构建与自动化验证不会安装业务软件，也不会复制 `Local Installer` 中的安装包进入产物。

构建使用仓库中的 `evidence/` 公开摘要，不依赖本地测试产生的 `artifacts/`、已安装业务软件或历史主机快照。

京麦安装适配器使用 7-Zip 只读展开官方安装包。发布包保留 `licenses/7zip-license.txt` 和 `licenses/7zip-NOTICE.txt`，重新分发时应保留这些许可文件。

推送 `v*` 标签可触发 GitHub Actions 发布；标签需与应用版本相符（例如 `v0.14` 和 `v0.14.0` 均对应 `0.14.0`），并提供与标签精确对应的 `RELEASE_NOTES_<tag>.md`。流程完成测试、构建和压缩包检查后发布 ZIP 与 SHA-256 文件，已公开的同名 Release 不会被覆盖。

配置仓库 Secret `GITEE_TOKEN` 后，`main` 提交会自动同步代码，成功的 GitHub 发布会自动同步标签及原始 ZIP、SHA-256 附件到 Gitee。可在 `Sync HM AppKit to Gitee` 工作流手动补同步已有正式版。配置与故障处理见 [Gitee 分发说明](docs/gitee-migration.md)。
